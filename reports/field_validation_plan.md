# 重庆轨道步行模型低成本现场验证计划

制定日期：2026-10-17（Asia/Shanghai）

## 1. 验证目标

用少量真实步行记录回答两个问题：

1. 固定4.5 km/h模型与SRTM坡度模型，哪一个对住宅区到轨道站的实际步行时间误差更小？
2. 误差主要来自速度函数，还是来自小区大门、道路缺失、楼梯、过街等待和立体连通错误？

本计划不把在线地图预计时间作为真值。真值来自同一研究者按统一规则实际步行并记录的时间、轨迹和道路条件。

## 2. 建议的8条路线

起点不能直接使用住宅面代表点。首次到现场时，应选择实际可进入小区且最接近模型路线的公共大门，并记录坐标；终点选择模型对应轨道站的具体地面出入口。

| 路线 | 住宅区→模型站 | 固定模型 | 坡度模型 | 选择理由 |
| --- | --- | ---: | ---: | --- |
| V01 | 荣鼎新苑→高庙村 | 5.8分 | 5.9分 | 短距离、爬升与下降接近平衡，作为近似平地对照 |
| V02 | 富洲新城二期→高庙村 | 13.7分 | 13.3分 | 朝车站总体下行，用于检查下坡是否被高估 |
| V03 | 电力小区→沙坪坝 | 13.2分 | 16.4分 | OSM路线含约40.9米楼梯边，检查DEM与楼梯差异 |
| V04 | 卓越·美丽山水→小龙坎 | 27.2分 | 32.6分 | 模型累计爬升约93.1米，坡度增时最大 |
| V05 | 升伟·新时空→马家岩 | 19.8分 | 24.4分 | 累计爬升约80.1米，覆盖马家岩方向 |
| V06 | 成都城投锦樾峰境→高庙村 | 19.6分 | 21.0分 | 改善候选；同时核验假设连接位置与-7.1%端点坡度 |
| V07 | 奇峰自由湾→高庙村 | 18.9分 | 22.0分 | 假设连接朝车站约+23.1%，检验陡坡与阻挡条件 |
| V08 | 大城小爱→高庙村 | 18.6分 | 19.6分 | 当前优先案例；核验长连接位置与实际绕行 |

如果时间有限，最低可执行组合为V01、V02、V03、V04、V07和V08共6条。V06—V08的现场步行只验证当前现实路线；不能穿越尚不存在或不可通行的假设连接。

## 3. 每条路线需要记录什么

### 必填字段

- `route_id`：V01—V08；
- 实际起点名称、经纬度和照片；
- 实际终点站名、出入口编号或现场标识、经纬度和照片；
- 开始、到达时间，精确到秒；
- 总历时和移动历时；
- 手机GPX轨迹或等价经纬度时间序列；
- 实际轨迹距离；
- 天气、路面干湿、日期和时段；
- 楼梯开始/结束点、台阶或楼层的大致数量；
- 上坡、下坡、坡道、天桥、地下通道、电梯和扶梯记录；
- 每次过街或等待的开始、结束时间；
- 封闭道路、门禁、挡墙、施工或OSM缺路；
- 是否偏离模型路线，以及偏离原因。

### 建议但非强制

- 手机气压高度或运动手表高程；
- 关键转折点照片；
- 主观体感：轻松、一般、费力；
- 是否携带行李、是否使用电梯或扶梯。

## 4. 低成本执行方法

1. 由同一名成年人完成全部主样本，保持正常通勤步速，不跑步。
2. 每条路线至少走2次，共16次；尽量在干燥天气、非极端拥挤时段完成。
3. 所有主测试均按“住宅区→轨道站”方向行走，因为当前模型评价的是进站可达性。
4. 如时间允许，对V02、V03、V04和V07增加反向步行，用于验证方向差异；反向结果单独分析，不能混入主样本。
5. 手机时间保持自动同步；开始前等待定位稳定，抵达指定出入口即停止。
6. 过街等待同时保留两种时间：总历时包含等待，移动历时尽量剔除明确静止等待。
7. 不为贴合模型而强行走不可通行或危险路线；发现阻挡时记录位置并走现实可行路径。

预计主样本总步行时间约5—7小时，可分2—3天完成。该估计只是工作量安排，不是现场测量结果。

## 5. 评价方法

对路线 \(i\)，固定模型与坡度模型误差分别为：

\[
e_{fixed,i}=\hat t_{fixed,i}-t_{observed,i},\qquad
e_{slope,i}=\hat t_{slope,i}-t_{observed,i}.
\]

主要指标为平均绝对误差：

\[
MAE=\frac{1}{n}\sum_{i=1}^{n}|e_i|.
\]

同时报告：

- 中位绝对误差，降低单条异常路线影响；
- 平均有符号误差，判断系统性高估或低估；
- 每条路线绝对误差，不只给总体平均；
- 固定模型与坡度模型的“胜出路线数”；
- 总历时和移动历时两套误差，以分离坡度误差与过街等待。

样本只有6—8条时不做显著性宣称，也不据此建立复杂机器学习模型。

## 6. 如何诊断模型表现不佳

| 观察结果 | 优先检查 |
| --- | --- |
| 两个模型都明显低估 | OSM漏路/误连、真实大门不同、过街等待、门禁或绕行 |
| 固定模型较准、坡度模型明显高估 | Tobler坡度惩罚过强、楼梯实际速度较快、DEM短边噪声 |
| 坡度模型较准且固定模型低估 | 坡度阻抗可能必要，但仍需更多路线确认 |
| 下坡路线坡度模型低估时间 | 下坡并未提高速度，可能受路面、台阶或安全减速影响 |
| 反向误差显著不同 | 方向性机制有价值，应分别校准上下坡 |
| 实际路线与模型路线不同 | 首先修正道路网络和入口，不应只调速度函数 |

## 7. 决策规则

- 若坡度模型MAE和中位绝对误差均低于固定模型，并且在平地、上坡、下坡和楼梯组中没有明显系统性恶化，可保留当前函数进入扩展验证。
- 若改进只来自1—2条极端路线，不调整全局模型，先扩大样本。
- 若主要误差来自入口和道路拓扑，优先修正OSM网络及起终点，而不是校正Tobler参数。
- 只有在至少包含多条上坡、下坡和楼梯的实测样本后，才拟合重庆本地坡度参数。

## 8. 数据整理模板

建议现场数据保存为`data/field/field_walk_observations.csv`，但在提交GitHub前应移除人脸、设备账号、家庭地址等个人信息。最低字段为：

```text
route_id,walk_id,date,start_time,end_time,direction,start_lon,start_lat,
end_lon,end_lat,gpx_distance_m,total_time_min,moving_time_min,
crossing_wait_min,stairs_present,weather,route_blocked,notes
```

GPX原文件可能包含出发前后的私人位置。公开前只保留研究路线段，并再次检查元数据和隐私。
